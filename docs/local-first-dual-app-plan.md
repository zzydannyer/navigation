# 无后端双端导航实施方案

日期：2026-11-17（香港时间）。本方案覆盖 dual-app-refactor-plan.md 中真实业务接口对接、联网搜索/AIS与缺接口使用模拟服务的安排。用户最新范围是：实现不依赖现有接口的全部主要导航功能，旧业务接口及调用链全部删除。当前仅给执行 AI 实施说明，不直接修改业务代码。

## 一、范围与联网边界

- Tauri 用 React/shadcn/ui + MapLibre GL JS；RN 用原生页面 + 原生地图 SDK，不允许 WebView 地图。共享本地业务状态、算法、数据格式和测试。
- 不建立后端、不接鸿蒙旧接口、不搬旧 token/签名/业务域名/用户系统，也不为未来后台留下未使用 service、mock server 或请求空壳。
- 生产运行唯一计划中的联网功能是官方公开底图及其必要样式、瓦片、字体、图标资源。源码文档链接、构建下载、开发服务器地址与生产业务请求分开审计。
- 官方指资源提供方自己的公开服务，不是随意选择第三方代理、公开演示镜像或拿到 URL 就可用。需核对官方说明、访问要求、署名、流量与离线使用规则。服务需要用户密钥或权限的，不作为默认方案。
- 地图渲染库不是海图数据源。默认底图不能标成具有水深/航道安全信息的官方航海图；不存在已验证可用、无需权限的全球精细海图服务时，产品使用公开基础地图 + 用户导入离线数据，不虚构数据源。

## 二、主要功能全部本地解决

### 地图与工具

实现缩放、平移、居中、跟随、北朝上/航迹向朝上、指北针、比例尺、经纬网、日夜主题、地图点选坐标、测距/连续测距、方位、范围全览、横竖屏。无真实船首向时不能把 GPS 航迹向标为船首向。

自建图层只含真实可得数据：本船、航点、航线、轨迹、用户导入 POI、用户导入边界。无航标/警告数据时不提供假业务图层开关。

### 航点与本地搜索

航点新增/改名/描述/坐标修改/删除、分类收藏、列表定位、批量导入导出。搜索本地航点、航线、轨迹和导入 POI；经纬度搜索采用本地解析，支持十进制度与度分秒，检验方向与范围。

港口搜索由用户导入有使用权的 POI 文件实现，本地检索名称/编号/类别和附近距离。没有港口数据时提示导入，不调用地理编码服务，不内置虚假港口结果。

### 航线编辑与规划

地图选点、插入/拖动/修改/排序/移除节点、撤销重做、名称与备注、航法选择、保存/复制/删除、全览、航段方位与长度、总航程。完成 React Hook Form/Zod 表单验证。

规划采用用户手工选点与本地几何计算。起终点之间连接只能称为手工航线，不能冒充避礁/绕陆/水深约束自动规划。港口间自动航线查询及付费定制航线入口直接删除。用户可从本地文件导入已有航线。

运行/暂停会话引用的航线和航点在状态层锁定；与地图拖动、表单编辑、导入合并、删除及撤销重做都使用同一守卫。

### 导航与仪表

复用已实现真实/模拟会话、当前位置有效性、到点推进、偏航、距离与 ETA。完善速度可调模拟、起停暂停恢复、地图当前航段和仪表一致性；零速度、结束和无定位有明确显示。

持续定位使用设备能力；NMEA 本批支持本地语句/文件回放，经同一真实输入入口校验。历史回放使用独立 replay/simulation 会话，不把旧时间数据伪装成新 GPS。串口/蓝牙/Wi-Fi 设备输入在具体设备可用后另立验证批次，不能声称已支持。

仪表显示位置、速度、航迹向、船首向、当前航段、下一点、全程剩余距离、ETA、偏航及定位新鲜度。无数据显示未知。

### 轨迹完整管理

显式开始/暂停/继续/停止记录，起止时间、名称、距离、时长、平均/最高速度；列表、详情、重命名、删除、地图全览、时间轴回放、倍速、跳转。跟踪记录与导航会话分开管理，不把暂停导航等同暂停轨迹。

不得继续依赖“所有轨迹截断为固定数量点”作为历史存储。改用分段/分页轨迹仓储；状态只持有摘要、当前段和显示抽样。原始点本地存储，地图显示可降采样。Tauri/RN 各自适配本地文件或数据库，具体库须先查官方文档。测算长时记录与退出时未落盘窗口，再决定落盘批次。

### 本地文件与离线数据

首批支持 GeoJSON（航点/线/POI）和 GPX（航点/航线/轨迹）导入导出；采用版本化本地 JSON 备份/恢复业务数据与设置。不导出权限或设备标识。

解析、校验、预览、重名/ID冲突决策、确认导入，禁止一读文件就覆盖现有数据。设置文件大小、点数、深度限额；失败保留原数据。导出回读验证关键字段与坐标，导入时处理撤销和活动会话锁。

PMTiles 沿已有 chart-core 继续实现可用闭环：选文件、读元信息、导入目录、开关显示、移除目录项与缺文件错误。Web 与 RN 原生 SDK 的本地资源接入分别验证，不能因为已有 reader 就认为能原生显示。不支持的压缩/格式明确拒绝。

不把 S-57/S-63/S-100 解码或加密许可支持混入这一批；需要专门引擎和数据验证后再实施。

### 基础设置

单位、经纬度格式、语言、日夜主题、跟随方向、轨迹采样规则、定位状态、数据目录、数据备份恢复和本地数据清理。设置本地持久化。TTS 暂不排期。

### 明确删除的联网功能

登录注册、短信、账号绑定、云同步、远程船舶/港口查询、在线 AIS 船队、线上历史轨迹、天气潮汐接口、实时航行通告、后台自动航线、商城/支付/VIP、SOS远程发送、推送、分享服务及其请求/鉴权/状态/按钮/依赖。

AIS 没有远程源则不显示在线船舶。以后用户有本地 AIS 接收设备时，可独立增加设备接入与目标解析，复用本地图层；本批不造实时目标。

## 三、官方底图方案与核验门槛

1. 开工先列官方候选和证据：OSM Standard 官方瓦片说明（https://operations.osmfoundation.org/policies/tiles/），MapLibre 官方文档和示例资源说明（https://maplibre.org/），如研究政府海图则仅使用其官方开放数据入口（例如 https://nauticalcharts.noaa.gov/）。候选不是已获准或已适配的结论。
2. 以无需后台与用户密钥、可在目标两端公开使用为默认源选择条件。官方演示服务只用作开发验证；不能把当前 demotiles.maplibre.org 当作已验收生产海图。
3. 样式自己维护，外部依赖逐一登记官方来源：style、瓦片、glyph、sprite、字体/图标许可与署名。禁止style间接访问未经核验的第三方域名。文件位置：Tauri 的 src/config/mapSources.ts 与 chart-web 的样式配置；RN 使用相应原生配置，业务层不存地图 URL。
4. 核验同一数据源在 Tauri WebView 与 RN 原生发布包的显示、中文符号/字体、经度换日线、署名、缩放、限流错误。OSM 等仅为地理背景，不承诺航海细节。
5. 禁止批量下载或离线预取不允许此用途的在线瓦片。离线采用用户合法取得的本地文件；飞行模式下导入海图、本地航线和轨迹可使用。未导入离线底图时仍可显示本地业务叠加及坐标，并明确底图不可用。

## 四、文件边界及接口清理

- apps/tauri/src/features：chart、waypoints、routes、navigation、tracks、imports、settings 页面；已有 RoutePanel 逐步承接，完成替代后删除旧重复入口，不留下两套逻辑。
- packages/nav-core：纯几何、导航、模拟与轨迹统计/回放计算；packages/navigation-app：本地用例、会话、应用状态和选择器。
- packages/platform-contracts：设备定位、存储、文件选择/读写、轨迹仓储等实际需要的端口；不建 HTTP 业务端口。
- packages/chart-core：数据目录、格式能力、地图输入/事件数据契约；packages/chart-web：仅 Tauri 的 Web 地图实现。
- apps/react-native：原生地图、原生表单与面板，平台 adapter；不得 import chart-web、DOM或Tauri模块。
- 清理扫描 src 中 fetch/axios/WebSocket/EventSource、业务 URL、token/签名、service/api/request 目录及调用方。删除旧业务请求后同步删除依赖与文案/页面入口。保留真正使用的系统能力调用和经核验地图请求。
- 已知本仓库运行源码目前主要外部数据地址为 chart-web/MapController.ts 中 MapLibre demo style；尚未发现已移入鸿蒙业务请求链。执行 AI 必须扫描所有源码及style资源复核，不因参考项目有接口就复制进来再删。
- 不修改 E:/project/Hongmeng 参考工程。仓库内不保留旧接口 mock/fixtures 伪装业务服务；测试 fixture 只用于明确的单测与导入样本。

## 五、执行顺序：两个应用按功能对齐

### B0：去接口与底图验证

完成生产网络资源清单和旧业务接口清理；选定官方底图或明确只提供本地底图模式；建立 RN 原生地图最小工程，验证真机发布构建、定位、共享包导入和本地图层。此后不再等待 Tauri 全部完工才开始 RN。

验收：源码无旧域名/鉴权残留；抓取运行请求确认仅官方底图必要资源；无账号仍可进入所有本地功能。RN 需原生地图运行证据，不能只有Metro启动日志。

### B1：航点、搜索、地图工具与本地导入

先完成共享用例及格式解析，然后两端分别实现UI。交付航点完整编辑、本地搜索、测距、GeoJSON/GPX预览导入导出、主题与朝向、横竖屏。

### B2：航线编辑及导航体验

两端完成节点插入/拖动/排序/删除、撤销重做、表单、全览、复制与导出；消费同一会话/选择器完成真实和模拟导航及仪表。补启动后进入真实会话、无定位、定位停止更新、权限撤回等可见状态。不接TTS。

### B3：轨迹管理与本地数据可靠性

分段仓储、显式记录、历史列表/统计/回放、备份恢复、文件错误和数据版本兼容。长时记录验证内存和持久化，不能只用几个点的单测验收。

### B4：离线地图及双端总验收

完成已验证格式的本地底图加载；断网下运行航点/航线/模拟/轨迹查看；真实GPS能否离线获取由目标设备实测。进行桌面和Android发布包验证，iOS待具备构建和设备条件后单独验收。

每批交付源码变更清单、真实可操作入口、自动检查和设备证据、未完成限制。共享逻辑单测可共用，Web和RN地图/权限必须分别运行验证。类型检查、测试、前端build通过不等同RN原生构建或实机通过。每轮仅追加自己的当日报告段落。
