**expo-doctor 1 项失败（疑似环境误报）**：
- 报 `.expo` 目录未被 git 忽略。但 `.gitignore` 第 7 行已是 `.expo/`；本机 git CLI 缺失，doctor 无法实际执行 git check-ignore 校验，故误报。按任务要求不顺手修范围外问题，记录在案。

**环境/策略问题（已绕过，需记录）**：
- pnpm 11.16.0 内置 supply-chain `minimumReleaseAge` 策略，拒绝昨天（2026-11-03）发布的 28~55 个 @expo/rollup 包。通过 `pnpm config set minimumReleaseAge 0 --location=global` 绕过。这些是项目已锁定的 SDK 58 依赖，非新引入风险。
- esbuild postinstall 被 pnpm 忽略导致 CI 模式 exit 1；通过 `pnpm approve-builds --all` 写入 `pnpm-workspace.yaml` 的 `allowBuilds` 解决。
- eslint 10.x 与 eslint-config-expo 58 自带的 eslint-plugin-react 7.37.5 不兼容（`contextOrFilename.getFilename is not a function`），故按兼容矩阵将 eslint 钉在 `^9`（9.39.5）。

## 数据基线落档

- **Waypoint DTO**：`{ id, name, position:{latitude,longitude}, description, createdAt }`。
- **Route DTO**：`{ id, name, waypointIds:string[], legKind: 'RHUMB'|'GREAT_CIRCLE' }`。
- **Track DTO**：`{ id, name, points: TrackPoint[] }`，`TrackPoint = { position, timestamp, speedKnots, courseDegrees }`。
- **持久化无版本号**：`readPersist` 仅 zod 校验当前形状，坏数据回退空状态，**无 migration/version 字段**——后续改 DTO 结构时需补版本号迁移。
- **TRACK_POINT_LIMIT = 2000**，`TRACK_MIN_NAUTICAL_MILES = 0.01`（移动不足阈值不记录）。
- **定位监听**：由移动端 `ChartScreen` 启停（`watchOwnShip`），不在核心包内。
- **store 订阅全量写 MMKV**：`useNavigationStore.subscribe` 每次状态变化都 `JSON.stringify` 全量写存储，目前数据量小可接受；随航迹增长需观察写入频率。
- **app.json**：`orientation=portrait`，`scheme=navigation`，plugins 含 expo-router/expo-dev-client/expo-status-bar/expo-build-properties/expo-location/expo-localization/@maplibre/maplibre-react-native。
