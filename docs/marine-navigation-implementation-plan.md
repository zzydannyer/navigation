# 平板海事导航实施与验收计划

日期：2026-11-04（香港时间）

## 1. 任务与原则

在现有工程上建设 Android 平板 / iPad 优先的离线海事辅助导航应用，覆盖 S-57、S-63、明确产品版本的 S-100 数据，以及 PMTiles。桌面保留现有 Tauri 骨架，暂不迁移 Electron。

本计划供执行 AI 分阶段实现，完成后由原对话 AI 审查差异、运行检查并核对设备证据。不要把全部阶段一次性塞进一个不可运行的大改动。每阶段都交付能运行的纵向功能和验收证据。

当前产品定位为辅助导航。标准化海图显示、航线安全辅助检查和 ECDIS 认证是不同层级；不宣称产品通过认证，不把任何算法结果表述为保证航行安全。

默认采用：现有 React Native / Expo 外壳 + 共享 TypeScript 导航业务 + 可替换海图处理/显示适配层。专业海图 SDK 优先验证；如果 SDK 必须自己渲染，允许其成为主海图视图。MapLibre 继续承担适合它的底图和业务图层，具体叠加方式以实测为准。

## 2. 已确认的工程起点

- 根工程 Expo ~58.0.23、React Native 0.88.1、MapLibre React Native ^11.5.1；这些是清单声明版本，执行前核对实际锁定和安装版本。
- pnpm workspace：`packages/*`、`apps/*`；已有 pnpm-lock.yaml，按现有管理方式执行，不另加锁文件。
- 移动入口：`src/map/ChartScreen.tsx`、`src/location/watchOwnShip.ts`、`src/store/navigationStore.ts`。
- 桌面：`apps/desktop`，Tauri 2、React、MapLibre GL JS。
- 共享核心：`packages/nav-core`，已有航点、航线、等角/大圆航段、偏航计算、轨迹和部分 NMEA 解析。
- 两端地图都使用 MapLibre 演示底图，不代表已支持海图。
- `app.json` 目前锁定竖屏；路由当前位于 `app/`，与 AGENTS 要求的 `src/app/` 不一致。
- 轨迹目前最多保留 2,000 点；定位监听由地图页面启动和清理，长期航行架构需要调整。
- 桌面地图使用全局 store 订阅触发绘制，需要检查是否重复提交未变化的数据。
- 工作区已有大量未提交修改。执行 AI 必须先记录基线，保留其他 AI 和用户已有工作，禁止 reset/clean 或批量覆盖。

以上是有限源码检查结果，不是完整代码审计；不要未经验证就把所有可疑点当成已确认缺陷。

## 3. 格式支持的可验收定义

### S-57

真实读取 ENC `.000` 基图及连续更新，保留对象属性、标识、关联、数据集元数据、覆盖范围、比例尺、质量及基准信息；能查询对象。支持范围与 S-52 显示规则覆盖范围分别记录，不能把读出几何称为完整海图显示。

### S-63

通过合法 SDK/实现和授权样本验证许可、认证、解密、更新及离线行为。不能将 S-63 当作普通文件扩展名解析；不能把受保护海图默认转存为明文瓦片。转换、缓存、日志和导出遵守供应商协议。

### S-100

第一批目标暂定 S-101 ENC，具体 edition / application profile 在技术验证阶段冻结。S-102、S-104、S-111 不自动纳入首批交付，必须单列产品、版本、样本、解析和显示能力。若供应商不支持所需版本，要明确未支持，不能声称支持全部 S-100。

### PMTiles

第一批支持已声明的 PMTiles v3 与常用 MVT 矢量、PNG/JPEG 栅格载荷，读取文件元数据并验证实际类型。其他载荷和版本显式返回不支持。实现本地离线随机读取、地图接入与资源完整性检查；有意损坏或异常大的文件必须安全失败。

## 4. 建议代码边界

保持当前移动工程位置，第一阶段不同时搬迁到 apps/mobile。建议按实际需要增加下面模块，不为未来格式批量创建空包。

- `packages/nav-core`：平台无关的导航模型、单位、几何、定位状态、航线和告警判定；不依赖 React Native、Tauri、文件系统和地图对象。
- `packages/chart-core`：海图目录、能力声明、导入状态机、海图元数据和错误模型、查询契约；不放受保护海图内容。
- `packages/chart-engine`：完成 SDK 验证后再建；共享的原生引擎/绑定实现，语言和构建方式由选定 SDK 决定。若并不需要独立包，不强行建立。
- `src/chart`：移动海图目录、导入流程、海图视图适配和展示配置。
- `src/services`：定位会话、设备连接、应用级任务协调。具体目录名称可贴合既有规范。
- `apps/desktop/src/chart`：桌面适配，不复制导航算法。
- `tests/fixtures`：有再分发许可的最小样本、生成器或下载说明；商业数据、密钥和许可证不提交。
- `docs/validation`：逐阶段验收记录、设备/版本/场景、命令结果与证据路径。大录屏和原始压测文件按仓库约定放忽略目录。

### 必需的契约语义

先用最少模型支持首个纵向功能，避免设计一个无所不包的统一 API：

- ChartSourceKind 区分 S57、S63、S101、PMTILES，不用一个 S100 枚举掩盖产品差异。
- 能力应按平台、SDK版本、产品edition以及操作声明：读取、更新、显示、查询、安全检查、离线；未知不能当支持。
- ChartDataset 包含来源、edition/update、覆盖范围、适用比例尺、更新时间、数据质量、有效性及必要基准；拿不到的字段标记未知。
- DisplaySettings 包含日/昏/夜模式、显示类别、符号设置、安全水深/安全等深线和单位。某设置无真实效果时禁用并说明，不显示假开关。
- Engine 接收文件句柄/受控资源标识及取消信号，返回任务ID、进度、诊断和版本结果；不通过 JS 传整份海图二进制或海量对象。
- 对象查询基于坐标/范围与海图版本，带稳定对象ID、来源和属性；显示命中与完整语义查询分开。
- 导入错误区分损坏、不支持、缺失更新、授权异常、空间不足、取消、运行时失败；使用稳定错误码并本地化展示。
- 渲染适配器负责 attach/detach、视角、点选、显示配置和业务叠加；海图SDK不支持的能力显式反馈。

## 5. P0：保护基线并建立可运行的检查（第一个交付批次）

1. 阅读实际 AGENTS.md 与相关子目录约定，记录 git status 和已有修改；不改写历史或提交无关工作。
2. 核对 package.json、锁文件、实际安装依赖、Node/pnpm/Rust 工具链；记录版本。
3. 操作 Expo/RN API 前读取 Expo 58 对应文档及具体模块文档。新增 Expo 依赖使用 Expo install 解析兼容版本；不能只改 package.json 猜版本。
4. 执行现有检查，区分已有失败与本次引入失败。缺失 lint 配置时使用匹配 SDK 的配置补齐；不以禁用规则、排除业务目录或增加大量 any 消除错误。
5. 增加明确的根/桌面/共享包 typecheck、lint、test 和桌面 build 命令；仅为需要验证的业务逻辑建立轻量测试框架。
6. 按 AGENTS 将移动路由迁到 src/app/，确认没有重复路由，并验证启动、标签页、路径别名和入口配置。
7. 保存当前航点/航线/轨迹交互基线及存储格式版本。迁移已有数据需要兼容处理。

验收：移动开发构建能启动；桌面开发版本能启动；lint、各包 typecheck、桌面前端 build 有实际结果；已有功能可回归。现有失败如未修好必须明确，不能标记全阶段通过。

## 6. P1：真实海图/SDK 技术验证（海图路线冻结关卡）

P0 后优先做这一阶段；P2 的独立基础能力可在等待供应商时推进，P3 及后续专业海图实现必须等待本阶段结论。

1. 建立合法样本清单：S-57 基图及更新、受保护 S-63 数据与测试许可、目标版本 S-101、矢量/栅格 PMTiles。
2. 评估至少一个可获得试用且可能满足 Android/iPad 的专业 SDK；有条件时与第二家对照。供应商网页声明不算设备验证。
3. 在目标 Android 平板和 iPad 上完成最小原生视图集成：读取、显示、点选、缩放旋转、离线启动；确认与当前 RN 架构及 Expo 开发构建兼容。
4. 验证安全水深变化、不同显示主题、字体/符号、跨图幅、多比例尺覆盖与更新后的对象变化。
5. 明确 SDK 的显示方式：自有原生视图、可嵌入渲染器或合法数据输出。SDK 自有地图时，验证业务图形叠加和事件映射；不要假设可叠两层 GPU 视图。
6. 核对许可：平台、按设备或订阅计费、离线时限、缓存和再分发、S-63/OEM接入、S-101版本、升级与支持政策。凭据不进入仓库和日志。
7. 输出 ADR：选定 SDK/自研路线、已验证平台与功能、缺口、成本报价来源、许可限制、主渲染方案、退出方案。

通过条件：至少在 Android/iPad 上用真实目标海图跑通必要能力并有证据。若暂缺许可证、SDK或设备，标记外部阻塞，继续 P2 和其他不依赖项；不能用 mock 代替通过。

若没有合适 SDK：先交付 S-57 辅助显示和 PMTiles；自研路线单独列成本与显示规则缺口。S-63 和 S-101 仍为明确未交付项，不悄悄删掉需求或标成完整支持。

## 7. P2：平板布局、离线目录与 PMTiles（首个用户可用闭环）

### 平板布局

- 支持横竖屏；宽屏采用地图+可折叠航线/仪表侧栏，窄屏保留合适导航；按可用窗口宽度而不是设备型号决定布局。
- 处理安全区、分屏、键盘、系统字体放大、旋转后的视角和选中对象保留。
- 触控目标建议至少约44pt（iOS）/48dp（Android）；避免地图手势与抽屉、航点拖动冲突。
- 已有中文/英文文案统一走现有 i18n。

### 海图目录及导入

- 用户选择文件/目录后通过平台权限机制导入到受管理存储或持久授权的资源位置；不能假设外部路径一直可读。
- 移动端验证 Android 文件授权和 iPad 文件提供者的实际行为。不要仅靠扩展名判断内容。
- 导入前检查格式、大小、可用空间、元数据和冲突；支持进度、取消、失败清理和重复导入。
- 临时写入后验证，再原子提交目录及索引；异常退出后能恢复或清理，旧可用版本保持有效。
- 清单存数据库或适合的结构化存储；大海图和轨迹不要塞进 Zustand/MMKV/localStorage。
- 目录展示已安装、更新中、失败、缺资源、授权状态及可用范围；未知状态如实显示。

### PMTiles 接入

- GL JS 使用匹配版本的协议读取适配；Native 根据当前版本能力选择原生 reader/桥接或受控本地瓦片服务，先验证再确定。
- 本地读取必须支持随机访问，不能每次瓦片请求重新读整个归档。
- 附带 style、sprite、glyph等资源清单和校验；飞行模式下无需演示服务器、在线字体或远程样式。
- 验证地图点击、缩放、旋转、切换海图、删除文件、损坏目录/偏移、超大解压数据和磁盘不足。
- 如果使用本地HTTP服务，限定回环接口和资源范围、正确处理范围请求与生命周期，不暴露整个磁盘。

验收：Android/iPad 断网、杀进程再启动后仍可打开导入的矢量/栅格样本；删除与失败恢复可用；没有隐式联网资源。PMTiles 仅证明瓦片能力，不作为 ENC 安全查询输入。

## 8. P3：S-57 解析、更新及语义查询

1. 按 ADR 集成真实海图引擎；采用 GDAL 时明确其只承担数据读取，S-52显示和安全语义仍需独立实现/引擎承担。
2. 支持交换集、基图、edition/update 和数据集完整性检查；按标准/SDK验证更新顺序、所属edition、缺失/重复更新和撤销状态。
3. 更新在隔离任务内执行，构建新语义存储/索引，验证成功后原子切换。失败或取消保留旧版本。
4. 保存原始对象身份、关键属性、关联、深度/高度单位、水平/垂直基准及质量信息；不只提取用于展示的几何。
5. 空间索引支持当前视窗和任意航线走廊查询。跨图幅、反经线、重复对象和不同编图比例尺处理策略写入 ADR。
6. 对象点选展示类型、名称、属性、来源图幅、版本和数据时间；查询未命中/区域无覆盖不能显示“无危险”。
7. 验证水深点、深度区、等深线、岸线、障碍物、灯标等代表性对象；显示类别、缩放过滤、安全等深线选择和符号规则按实际支持项核对。

验收：固定真实样本导入后对象数量/关键属性可复现；更新前后指定对象变化与可信工具输出或供应商参考结果对照；缺失更新不静默成功。专业显示规则未覆盖的内容必须列出。

## 9. P4：S-63 授权海图闭环

- 通过所选 SDK 正式接口接入测试许可，验证信任链、许可不匹配、数据损坏、续期、更新和离线重启。
- 按 SDK/标准和商业协议定义有效、过期、无效状态的可用行为，不自行发明过期处理规则。
- 许可证、安全凭据和受保护数据存放在允许的位置；日志、崩溃信息、截图和测试产物检查泄露风险。
- 更新过程仍保持版本原子切换与失败恢复；删除图幅时按协议清理相关缓存。
- 不提供未授权解密、绕过许可或明文导出路径。

验收：合法样本在两类平板设备上可离线运行，授权失败结果符合 SDK/供应商规则；测试证据隐藏敏感内容。无授权样本时本阶段保持未验收。

## 10. P5：明确版本的 S-101

- 在 ADR 记录支持的 S-100/S-101 edition、目录/显示资源版本、保护机制、SDK版本和样本来源。
- 验证交换集导入、对象/信息关联、更新与撤销，以及产品规定的显示目录与规则。
- 不能复用 S-57 字段映射后就声称完整支持 S-101；数据结构、显示和更新能力逐项确认。
- S-57/S-101 混合覆盖时确定选图、比例尺、版本和重复要素策略，UI 显示当前海图来源。
- S-102/104/111 作为后续独立产品：各自做数据模型、时间维度、基准、版本和显示验证，再启用能力声明。

验收：声明版本的真实样本在 Android/iPad 可导入、查询、显示、更新；不支持的产品/edition有可理解错误。宣传与能力声明一致。

## 11. P6：导航会话、设备与海图安全辅助检查

### 航行会话和存储

- 定位监听归应用级航行会话管理，地图切页或重建不能重复订阅或意外停止。停止/取消会话后释放资源。
- 前台航行先完成；后台定位单独按平台权限、后台模式和用户控制验证。iOS限制、仅Wi-Fi iPad的定位能力和外置GNSS接入要写明，不承诺任意设备后台常驻。
- GPS对地航向 COG 与真艏向 heading 分开；无法取得时保留未知，不能以0或其他值伪造有效读数。
- 定位有有效、过期、无定位、错误等状态；显式记录数据来源、接收时间和观测时间，处理权限变化、断线重连和异常输入。
- 长轨迹写入数据库并分段/索引，地图仅加载需要的简化显示片段；保留完整历史，不能继续只靠2000点滑窗承载航行记录。
- 存储损坏、JSON异常、写入失败和schema迁移能恢复或报错，不能静默丢失用户路线。

### NMEA / AIS

- 优先支持 Wi-Fi TCP/UDP 或 Signal K 的一种真实设备通路，先打通一个端到端流程；USB/串口/BLE按平台能力单列，不一次铺满空接口。
- NMEA 流式分帧、校验、坏包隔离、输入上限、超时重连；单条解析失败不能终止连接。
- AIS 支持 VDM/VDO 分片重组、序号冲突/过期、静态与动态信息、不可用值和目标老化；测试代表性消息类型并公布支持范围。
- 不把 AIS 航迹、GNSS 艏向和推算位置混为真实测量值。预测位置应有明确标识。

### 安全辅助检查

- 仅在海图语义和基准足够时实现。按航线和船舶参数建立走廊，查完整空间索引，不能依赖当前缩放下的可见瓦片或图层。
- 检查水深、障碍、限制区域等已支持条件；定义吃水、安全余量、深度基准、潮位来源和数据质量。
- 潮位/基准不能可靠换算时不得给出通过结论；无海图覆盖、过期数据或不支持对象类型返回“资料不足/未检查”。
- 结果区分已完成检查且未发现问题、发现问题、无法完成；附带海图版本、参数、时间、覆盖范围及局限。
- CPA/TCPA 明确数据时效、速度模型、坐标方法和零相对速度处理；报警考虑去重、迟滞和确认状态。
- 默认不启用自动驾驶输出，不因OpenCPN支持就纳入首期范围。

验收：切页与旋转不丢会话；权限/断连/无效定位有明确状态；长轨迹可重启恢复；安全检查有已知危险、无覆盖、基准未知等反例测试，不允许未知转为安全。

## 12. P7：桌面补齐和跨平台发布验证

- 在海图引擎确定后验证桌面SDK可用性；不因为已有GL JS界面就假设专业海图能力可移植。
- 优先 Windows，macOS/Linux 按实际目标设备验证；某平台SDK缺失必须如实列出。
- 复用 chart/nav 契约，平台特有文件权限、设备接入和原生视图放适配层。
- 只有发现可复现且影响目标功能的 WebView 问题，或团队维护成本明显不合适时，再单独评估 Electron；禁止本轮提前迁移。
- 桌面地图原生/GL JS显示差异用同样例、视角和设置核对；不能要求像素绝对一致，但关键对象和语义不能不一致。
- 签名、开发构建/正式构建、升级迁移与离线安装分开验证。无 macOS 构建环境/证书时明确构建和真机验证边界。

## 13. 性能计划与暂定门槛

以下为工程目标，不是已测结果或供应商能力承诺。P1 记录目标最低设备型号、OS、内存、GPU和应用构建配置后冻结指标；若必须调整，给出测量证据和原因。

- 每个平台至少一台目标设备，Android至少覆盖目标低配档；使用release或接近release配置。
- 记录样本字节数、海图数量、对象数量、覆盖区域及样式设置。相同视角、数据和刷新频率下比较。
- 核心场景：离线冷启动、导入/更新、连续缩放旋转、跨图幅切换、对象点选、航行轨迹记录。
- AIS测试档位100/1000/5000个可见目标；1000档以每秒一次动态批量更新为起始目标；5000档为压力测试，不作默认容量承诺。
- 交互目标：1000档及代表性复杂海图下缩放/旋转至少稳定30fps档，p95帧耗时目标不超过33.3ms；声明使用的测量工具和统计口径，不能只看平均fps。
- 常规点击反馈目标200ms内，复杂对象查询目标1秒内；后台长任务即时显示进度并可取消。
- 禁止主UI/JS线程执行整图解析；航行过程中避免持续大于100ms的JS任务，记录例外和来源。
- 连续缩放30分钟、连续航行回放8小时；无崩溃、内存不足退出或无解释数据丢失。稳态内存、峰值、热降频、耗电按设备记录，内存预算在P1基于设备和SDK实测设定。
- 24小时轨迹以1Hz输入生成86,400个观测点，记录采样策略和实际持久化数量；显示可简化，不能静默截断历史。
- 检查重复订阅、重复setData、全量store序列化和全量轨迹重绘；静态/动态数据分离，合并更新并实施背压。

## 14. 自动检查与设备证据

执行AI在P0建立可重复命令。根据实际安装方式运行并记录准确命令和退出码，建议对应：

```text
pnpm exec expo lint
pnpm exec tsc --noEmit
pnpm --filter @navigation/core exec tsc --noEmit
pnpm --filter @navigation/desktop exec tsc --noEmit
pnpm --filter @navigation/desktop build
pnpm exec expo-doctor
cargo check --manifest-path apps/desktop/src-tauri/Cargo.toml
```

expo-doctor若不是已安装可执行项，使用合适的pnpm dlx并记录版本；新增包也加入自己的检查。Rust测试在引入对应逻辑后运行。命令可按实际工具链修正，但不能省略移动/桌面/共享包的类型与lint检查。

有价值的自动测试集中在：

- 导入状态机取消/失败/断电恢复与版本原子切换。
- S-57更新、坏海图、未知edition、缺失资源和目录边界校验。
- 坐标顺序、单位、反经线、无效数值、时间戳、未知艏向与定位过期。
- NMEA坏包/分帧，AIS分片过期/冲突及不可用值。
- 航线检查的危险反例、无覆盖和基准未知；CPA/TCPA退化情况。
- 存储迁移、损坏恢复、长轨迹不丢失及重启恢复。

mock只用于契约和错误分支；真实解析器必须有合法格式样本验证。不要写仅复述实现的测试，也不要用截图代替数据正确性检查。

移动端验证记录：设备型号/OS、构建版本、样本ID与校验值、操作步骤、预期/实际、日志/录屏位置；第三方SDK版本和许可证信息只记录脱敏标识。

Windows上静态检查通过不能证明iPad可用；没有设备/构建环境的项目明确标记“未验证”，不能由模拟器或浏览器结果替代。

## 15. 提交批次与完成定义

推荐按顺序形成独立可检查批次：

1. P0：工程基线、检查命令、路由一致性与回归。
2. P1：SDK真实样本技术验证、ADR和能力清单。
3. P2：平板界面、离线目录、PMTiles闭环。
4. P3：S-57基图、更新、显示与语义查询。
5. P4：S-63授权闭环。
6. P5：指定版本S-101。
7. P6：长期航行会话、轨迹与设备、安全辅助检查；可再拆成多个批次。
8. P7：桌面与发布验证、性能收口。

每批提交审查包：目标与范围、改动文件、已运行命令与结果、真实样本来源/许可、设备证据、已知问题、未完成项、下一阶段前置条件。不要未经用户要求推送/发布；本地可检查差异不要求先做远程PR。

总体验收要求：S-57、S-63、指定S-101、PMTiles的支持范围与真实验证结果一致；不能把只完成P2称为完成整个导航项目。
